Shared chrome. All three variants share the same chrome: rgba(11, 15, 25, 0.92) fill, 12 px backdrop-blur, --wh-shadow-3, the 20 × 20 logo button on the left (clickable across all variants — sends OPEN_POPUP to the service worker), sans-medium-12 message, dismiss × on the right. Only the border tint, the position, and the message content differ.

Why split info into info + auto. AutoModeToast and NoParagraphNotification currently render identically; the only differentiator is the message string. They carry opposite intents — "the mode is doing work for you" vs "this page can't run a hunt" — and giving them separate visual identity lets the player parse them in a glance instead of reading. The soft primary tint on auto ties back to the brand metaphor: the highlighter is at work, even when the popup is closed. We deliberately keep the same logo glyph across all variants so the "tap to open" affordance stays consistent — the border tint and the in-message active-word do the differentiation.

No new token. The auto border uses an inline rgba(…) derived from --wh-primary; if we end up reusing the same tint in more places (a subtle "mode active" ring on the BottomActionBar toggle, for example) we should promote it to --wh-primary-faint at that point — premature now.

Copy update. AutoModeToast message becomes "Auto-Hunter active · <Word>" so the player can verify the current target without opening the popup. The active word is rendered in mono + --wh-primary (it is a word, and it's the live one). Highlighting the word is optional polish — the toast reads fine without it — but it lifts the active-word out of the sentence and makes the toast feel like a status line, not a sentence.

Mutual exclusion still holds. info (no-paragraph) wins over auto on the same page load — no point announcing the mode when no hunt is going to start.
